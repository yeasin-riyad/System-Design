# 🔹 System Design কী? 

**System Design** হলো এমন একটি প্রক্রিয়া যেখানে একটি Software System-এর বিভিন্ন অংশ কীভাবে একে অপরের সাথে কাজ করবে, তা নির্ধারণ করা হয়। 

সহজ ভাষায়: 

> **System Design = একটি Software System-এর Architecture, Components, Data Flow এবং Interaction কীভাবে কাজ করবে তা পরিকল্পনা করা।** 

System Design-এর মূল উদ্দেশ্য হলো নির্দিষ্ট কিছু **Requirements** পূরণ করার জন্য একটি কার্যকর ও নির্ভরযোগ্য System Architecture তৈরি করা।

🧠 Golden Rules🥇 Rule 1 — প্রতিটি Component-এর পেছনে কারণ থাকতে হবেDiagram-এ অনেকগুলো Box থাকলেই Design ভালো হয় না। প্রতিটি Component-এর জন্য প্রশ্ন করতে হবে: আমি এটি কেন ব্যবহার করছি?🥈 Rule 2 — Simple Design is Better❌ Most Complex Design ≠ Best Design✅ Most Appropriate Design = Best Design🥉 Rule 3 — Requirement অনুযায়ী Design করোSystem Design শুরু করার আগে Functional ও Non-Functional Requirement পরিষ্কারভাবে বুঝে নিতে হবে।💻 Design বনাম ImplementationImplementationSystem DesignCode-level details (Class, Function, Variable, Algorithm, Database Query)System-level architecture and component interactionএই Function কীভাবে কাজ করবে?এই পুরো System কীভাবে কাজ করবে?🎯 System Design Interview Approachএকটি ভালো Flow:Requirements Clarify করো (Users, Traffic, Data size, Features)Estimate Scale (Traffic, Storage requirements)High-Level Design (Simple Architecture থেকে শুরু করা)Data Design (SQL vs NoSQL, Schema, Index, Source of Truth)API / Interfaces (REST, gRPC, Input/Output)Scalability (Horizontal Scaling, Caching, DB Replication, Sharding)Failure Handling (Server crash, DB down, network issues)Trade-offs (Performance vs Consistency, Complexity vs Scalability)🚀 Simple থেকে Large Scale (Evolution)Level 1 (Basic): Client → Server → DatabaseLevel 2 (Scaling): Client → Load Balancer → Multiple Servers → DatabaseLevel 3 (Performance): Client → Load Balancer → Servers → Redis → DatabaseLevel 4 (Async): Client → API Servers → Queue → WorkersLevel 5 (Large Scale): Client → Load Balancer → API Servers (Cache, DB, Queue, Object Storage)✅ System
